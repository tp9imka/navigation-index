# GNSS-SDR - integration card
<!-- about: repo:gnss-sdr/gnss-sdr -->
A complete software GNSS receiver: IQ samples in (file or SDR front-end), observables, RINEX, NMEA, RTCM and a PVT fix out, with per-channel correlator, C/N0 and tracking telemetry streamed over UDP. The tool for signal-level jamming/spoofing experiments and Galileo OSNMA.

Snap `gnss-sdr-next`, or Docker images from carlesfernandez/docker-gnsssdr (README "Other builds"). From source (latest tag `v0.0.22`, 2026-10-04): install the README's apt dependency list (`gnuradio-dev gr-osmosdr libarmadillo-dev libboost-*-dev libprotobuf-dev libpugixml-dev libssl-dev libuhd-dev libmatio-dev protobuf-compiler python3-mako ...`), then `cmake -S . -B build && cmake --build build`. ## Minimal usage
This listing was not run as written; the hub's gnss-signal-chain sample ran the same file-source pattern with 0.0.19 (see Verified in this hub). Post-processing a file captured with or generated by [GPS-SDR-SIM](./osqzss__gps-sdr-sim.md) (int16 I/Q, 2.6 MS/s, baseband). Start from a shipped GPS L1 file conf and change only these keys (key names from README "Getting started"):

```ini
GNSS-SDR.internal_fs_sps=2600000
SignalSource.implementation=File_Signal_Source
SignalSource.filename=./gpssim.bin
SignalSource.item_type=ishort
SignalSource.sampling_frequency=2600000
SignalConditioner.implementation=Signal_Conditioner
PVT.implementation=RTKLIB_PVT
PVT.positioning_mode=Single
PVT.enable_monitor=true
PVT.monitor_client_addresses=127.0.0.1
PVT.monitor_udp_port=1234
```

```bash
gnss-sdr --config_file=./gpssim_l1.conf
```

Decode the UDP stream in Python with `protoc --python_out=. docs/protobuf/monitor_pvt.proto` and a plain socket on port 1234.

## Wiring it into a nav stack
- Test-signal loop: [GPS-SDR-SIM](./osqzss__gps-sdr-sim.md) file => GNSS-SDR => RINEX => [RTKLIB](./rtklibexplorer__rtklib.md) or [gnss_lib_py](./stanford-navlab__gnss_lib_py.md). Fully offline, no RF.
- Interference detection: subscribe to `gnss_synchro` (C/N0, lock flags) and `monitor_pvt` (position jumps, clock) and score them, same logic as the [gnss-interference-monitor sample](../../samples/gnss-interference-monitor/README.md) uses on u-blox telemetry.
- Authentication: GNSS-SDR decodes Galileo OSNMA itself (v0.0.22 changelog: Chain/Merkle renewal, alert messages, `GNSS-SDR.osnma_mode=replay` for recorded signals), and can also feed [OSNMAlib](./algafix__osnma.md) over UDP.
- Autopilot / ROS: NMEA to a pseudo-TTY (`PVT.flag_nmea_tty_port=true`, `PVT.nmea_dump_devname=/dev/pts/N`) for any NMEA GPS driver; RTCM out on TCP for a downstream RTK engine.
- Ecosystem: gnss-sdr-monitor (Qt GUI for the UDP monitor) and a ROS 2 bridge exist in the gnss-sdr org (not indexed here, not checked).

## Gotchas
- `SignalSource.sampling_frequency`, `GNSS-SDR.internal_fs_sps` and conditioner rates must all agree with the file. Mismatch => acquisitions but no tracking, or no PVT. Several open issues are this (#844 "No sync from GPS data file", #234 "No PVT while tracking 4 or more satellites").
- `item_type` must match the sample format: GPS-SDR-SIM default `-b 16` is `ishort`; `-b 8` is `ibyte`. GPS-SDR-SIM issue #212 is about `.bin` vs `.dat` naming - the extension does not matter, the item type does.
- Build breakage tracks dependency churn: open #972 CMake fails with Boost 1.90+ (`boost_system` package removed); closed #835 Homebrew install problems on macOS 15.2. On a hackathon laptop prefer the apt package or Docker (Ubuntu 24.04's 0.0.19 package ran on arm64 in the hub).
- Live front-ends: GNSS L1 needs active-antenna bias power (README notes the USRP daughterboard jumper). On RTL-SDR/HackRF check the dongle's bias-tee is enabled or use a powered splitter.
- Real-time on weak CPUs (Pi, laptop on battery) drops samples; post-process recorded files instead.

## Verified in this hub
Measured by hub samples that ran this code on 2026-11-06, unless a bullet says otherwise. The linked sample README holds the commands and raw output.

- **0.0.19 from Ubuntu 24.04 `noble/universe`** (prebuilt arm64) post-processed gps-sdr-sim files in Docker on Apple Silicon: clean run median 2.9 m horizontal error, 15-74 s per 150 s scenario. Runs are not bit-identical (thread scheduling: first fix t=43 vs t=49, 59 vs 54 epochs) - [gnss-signal-chain](../../samples/gnss-signal-chain/README.md).
- **Unaligned spoofer + authentic signal (file mix)**: 0.0.19 was not captured but lost PVT; logs showed repeated `Sent reset to observables` and ~-80 ms clock corrections, pseudoranges offset ~-23,982 km, so every solution failed RTKLIB's chi-square. Code/carrier-aligned drag-off was followed smoothly to ~1 km. C/N0 for a +8 dB spoofer read 49-51 dB-Hz, not the targeted 55 (not investigated). Clock drift is not in the 0.0.19 `pvt.mat` dump - [gnss-signal-chain](../../samples/gnss-signal-chain/README.md).
- **OSNMA in 0.0.20** (source build, aarch64 Docker, 1.74 GB, ~200 s) on an OSNMA-SDR-SIM E1 file: public key and DSM-KROOT signature verified, TESLA keys verified, strict mode rejected the replayed file (`time constraint violation`, 0 PVT). Tag and navigation-data authentication **not** verified (`d_tags_awaiting_verify :: size: 0`, every entry `verified=0`); cause not found. 0.0.20 segfaults (exit 139) on the simulator's short-form public-key XML; a PEM of the same key works - [osnma-authentication](../../samples/osnma-authentication/README.md).
- Strict mode keeps a Galileo observable only if PRN + `IOD_nav` are authenticated (`rtklib_pvt_gs.cc`, by code reading); the same-IOD gap seen in OSNMAlib likely applies (not tested) - [osnma-authentication](../../samples/osnma-authentication/README.md).
- 0.0.19 writes no RINEX epoch for a second without PVT, so a denial shows up as missing epochs, not flagged ones; a monitor has to treat the gap itself as the alarm - [gnss-signal-chain](../../samples/gnss-signal-chain/README.md).

## Alternatives
- [PocketSDR](../../catalog/repos/tomojitakasu__pocketsdr.md) - lighter Python/C receiver by the RTKLIB author, broader signal list, simpler to hack; less production tooling.
- [GNSS-DSP-tools](../../catalog/repos/pmonta__gnss-dsp-tools.md) - minimal Python acquisition/tracking on IQ recordings; best for understanding or quick per-signal checks, no PVT pipeline.
- [SoftGNSS-python](../../catalog/repos/perrysou__softgnss-python.md) - textbook GPS L1 receiver in Python for teaching-scale experiments.
