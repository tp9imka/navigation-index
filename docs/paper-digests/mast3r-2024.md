## Problem
2D matchers fail under extreme viewpoint change (up to 180 deg, opposite-facing views). DUSt3R, a pointmap-regression 3D reconstruction network, is very robust to this but its correspondences are imprecise. MASt3R adds explicit matching to DUSt3R to get both robustness and pixel accuracy.

## Method
- Backbone: DUSt3R (ViT-Large encoder, ViT-Base decoder, cross-attention between the two views), initialized from the public DUSt3R checkpoint (Sec. 4.1).
- Per pixel it outputs a 3D point (pointmap in camera 1 frame), a confidence, and a new 24-D local descriptor from an added MLP head (Sec. 3.2, App. D).
- Losses: DUSt3R confidence-weighted 3D regression (made metric when ground truth is metric) + InfoNCE matching loss over ground-truth correspondences, weight 1.
- Fast reciprocal matching: start from k sparse seed pixels, iterate NN back and forth until cycles (mutual matches) form. Complexity O(kWH) instead of quadratic; also improves pose accuracy because it samples matches more evenly (App. B).
- Coarse-to-fine: network works at 512 px max; for high-res images, match at low res, then match overlapping 512 px window crops covering 90% of coarse matches.
- Training: 14 datasets (Habitat, ARKitScenes, BlendedMVS, MegaDepth, Static Scenes 3D, ScanNet++, CO3D-v2, Waymo, Map-free, WildRGB, Virtual KITTI, Unreal4K, TartanAir, an internal dataset), 35 epochs x 650k pairs.

## Data and sensors
Uncalibrated monocular image pairs; outputs metric-scale pointmaps when trained metric. Evaluated on Map-free relocalization, CO3Dv2, RealEstate10K, Aachen Day-Night, InLoc, DTU. TartanAir is in the training mix ([card](../dataset-cards/tartanair.md)), so do not use it as a held-out test.

## Headline results (as reported)
- Table 2, Map-free test: MASt3R (auto, own metric depth) VCRE AUC 0.933, median pose error 0.36 m / 2.2 deg; previous best LoFTR+KBR AUC 0.634, 2.23 m / 37.8 deg. MASt3R matching with DPT depth: AUC 0.726, 0.80 m.
- Table 1, Map-free val ablation: matching descriptors beats matching 3D points (AUC 0.752 vs 0.732, same DPT depth).
- Table 3, RealEstate10K mAA(30): MASt3R 76.4 vs DUSt3R pairwise 61.2, DUSt3R-GA 67.7. CO3Dv2 RRA@15 / RTA@15 / mAA(30): 94.6 / 91.9 / 81.8.
- Table 4, InLoc DUC2 top40: 71.0 / 87.0 / 91.6 vs LoFTR 54.2 / 74.8 / 85.5. Aachen night top20: 76.4 / 91.6 / 100, roughly on par with SP+SuperGlue 77.0 / 90.6 / 100.
- Table 4, direct pose regression (no matching) top1 on Aachen day: 1.5 / 4.5 / 60.7. Regression alone fails on large scenes.
- Fig. 3 right: fast reciprocal matching with k=3000 is 64x faster than full matching (timed on a single CPU core) and improves VCRE AUC.
- App. C Table 5: coarse-only matching drops Aachen night top1 from 70.2 to 55.5 at the tightest threshold.
- GPU inference time per pair: not located in the paper.

## Limitations
- Stated by authors: network limited to 512 px input (attention cost), needs coarse-to-fine for high-res; dense reciprocal matching is prohibitively slow without subsampling; direct regression is unreliable on large scenes.
- Our read: ViT-L encoder + ViT-B decoder per pair is heavy; real time on a Jetson is unlikely. Map-free gains are partly from metric depth, which matters for single-reference relocalization, not for large-area geolocalization. No aerial or satellite evaluation.

## What a hackathon team can take from it
- Relocalization when views barely overlap or face each other: e.g. re-acquiring a pose against a single stored reference image after a long GNSS outage. Low rate, offline or on a ground station.
- Fast reciprocal matching (seed, ping-pong NN, keep cycles) is a reusable trick for any dense descriptor map, including RoMa-style or XFeat* outputs; it doubles as spatially even match sampling for RANSAC.
- Metric pointmaps from two images give scale without a stereo rig; useful as a sanity check on monocular VO scale, not as a primary sensor.
- Run it side by side with RoMa / LightGlue on your own pairs via [vismatch](../integration-cards/gmberton__vismatch.md); keep the NC license in mind before building anything on it.
