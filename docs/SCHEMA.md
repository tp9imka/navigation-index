# Data schema

The source of truth is JSON under `data/`. Everything else (catalog pages, indexes,
graph) is generated by `tools/build.py`. Never hand-edit generated files.

```
data/concepts.json          taxonomy nodes (fixed vocabulary, ids "concept:*")
data/repos/<lane>.json      array of repo records, one file per research lane
data/resources/<lane>.json  array of resource records (papers, talks, docs, courses...)
data/github_meta.json       generated by tools/enrich.py (stars, license, pushed_at)
```

## IDs

- Repo: `repo:<owner>/<name>` lowercased, taken from the canonical GitHub URL
  (e.g. `repo:px4/px4-autopilot`). Non-GitHub repos (GitLab, Codeberg, Bitbucket):
  `repo:<host>/<owner>/<name>`, e.g. `repo:gitlab.com/gnss-sdr/foo`.
- Resource: `res:<short-kebab-slug>`, e.g. `res:groves-pnt-book-2e`. Make slugs specific
  enough to avoid collisions across lanes (prefix with org or author when unsure).
- Concept: only ids that exist in `data/concepts.json`.

Cross-lane links work because repo ids are derived from URLs: you can reference any
GitHub repo by id even if another lane indexes it. The builder reports dangling ids.

## Repo record

```json
{
  "id": "repo:px4/px4-autopilot",
  "kind": "repo",
  "name": "PX4 Autopilot",
  "url": "https://github.com/PX4/PX4-Autopilot",
  "summary": "1-3 sentences in our own words: what it is.",
  "why_it_matters": "1-2 sentences: why a navigation / defense hackathon team would care.",
  "concepts": ["concept:autopilot", "concept:sensor-fusion"],
  "tags": ["ekf2", "uav", "c++"],
  "language": "C++",
  "domains": ["air"],
  "maturity": "production | active-research | research-prototype | archived | educational",
  "hackathon_fit": "high | medium | low",
  "hackathon_notes": "Concrete way to use it in a 24-48h build. Setup cost, gotchas.",
  "related": [
    {"id": "repo:mavlink/mavsdk", "rel": "integrates_with"},
    {"id": "repo:ardupilot/ardupilot", "rel": "alternative_to"}
  ]
}
```

`domains`: any of `air, ground, maritime, underwater, space, dismounted, multi`.
`rel` values: `depends_on, integrates_with, alternative_to, fork_of, extends, evaluated_on, same_org`.

## Resource record

```json
{
  "id": "res:magnav-challenge-site",
  "kind": "paper | talk | course | lecture-series | masterclass | doc | standard | book | dataset | report | blog | competition | podcast | video",
  "title": "Exact title",
  "url": "https://...",
  "authors": ["Org or people"],
  "year": 2021,
  "summary": "2-4 sentences, own words.",
  "key_takeaways": ["short bullet", "short bullet"],
  "concepts": ["concept:magnetic-nav"],
  "tags": ["afrl", "airborne"],
  "level": "intro | intermediate | advanced",
  "access": "open | free-registration | paywalled",
  "related": [
    {"id": "repo:magnav-jl/magnav.jl", "rel": "has_code"},
    {"id": "res:other-resource", "rel": "cites"}
  ]
}
```

Resource `rel` values: `has_code, uses, evaluates, cites, explains, dataset_for, part_of, same_author`.

## Rules for contributors (human or agent)

- Only include items you have verified exist (URL resolves / `gh api repos/<o>/<n>` succeeds).
- Summaries in your own words. No copied README text beyond a short phrase.
- No invented numbers. Leave stars/license to `tools/enrich.py`.
- Navigation, localization, PNT resilience, situational awareness and defensive EW
  are in scope. Weapon terminal guidance, targeting and offensive payload content are out of scope.
