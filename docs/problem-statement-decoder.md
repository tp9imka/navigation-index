# Problem-statement decoder

Plausible problem statements for a navigation / PNT / GNSS-denied hackathon, each mapped to a
recommended approach, a stack (integration cards first, catalog pages otherwise), datasets, a
sample or template to start from, the main risk and a one-line pitch. Use it in the first 20
minutes of [day 0](day0-runbook.md): match the real statement to one to three rows, then score
them with the rubric there.

Written 2026-11-06. The statements are paraphrases of the kind funders and past hackathons
publish ([programs and challenges](landscape/programs-and-challenges.md),
[UA/RU hackathon tracks](landscape/ua-ru-sources-overview.md)), not leaked briefs. Dataset sizes
come from the [dataset cards](dataset-cards/README.md) (checked against the host, not
downloaded). Card snippets were read from source, not run. Pitches contain no numbers on
purpose: put in the number you measure.

Legend: "card" = [integration card](integration-cards/) (install, gotchas, license);
"Idea N" = project idea N in the [playbook](hackathon-playbook.md#3-project-ideas-24-48h);
[project-repo](../templates/project-repo/) = the template skeleton
(PoseSource => NavFilter => IntegrityMonitor => Publisher, metrics included).
"Start from" lists samples best match first. Status, deps, first command and the key measured
number of each are in [samples/README.md](../samples/README.md); the numbers with their input
type (real / SITL / synthetic) are in [evidence-matrix.md](evidence-matrix.md). The "Start
from" column was refreshed on 2026-11-06 after review round 2 against every sample with a
`sample.json`.

Search tip: do not paste the statement into `tools/query.py search` or the MCP `search` tool.
Match it here first, then search with the row's keywords (repo names, method names, "jammer
localization sensor network TAK").
